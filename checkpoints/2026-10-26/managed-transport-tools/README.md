# PEX tool-enabled managed transport candidate — offline WIP

**299 offline tests pass. Functional source independently approved offline-only. All public live entry points remain denied.**

This separate candidate preserves text-only v1 and guarded PEX production unchanged. Its owned direct HTTPX path validates exact raw usage before tool replies, enforces required/named choices, bounds JSON/bodies, and inspects decoded copies of known embedded argument/evidence JSON for current-credential echoes. Original evidence text remains unchanged; this is not arbitrary encoded-secret detection.

`tool_protocol.py` binds COMPLETE authoritative PEX prompts and schemas to copied request/proposal identity. `strands_bridge.py` constructs code-owned bindings from a typed request/proposal and fixed route, not caller registries/callbacks/clients. It accepts only exact original or exact pinned-SDK-normalized presentation copies; authoritative schemas on the wire are never weakened or shortened. Framework runtime state is tied to the private owned Agent/model/messages/current trace and cycle IDs, with exact known metadata shapes. None of that runtime state is transmitted to HTTP.

The private buffered bridge owns its committed causal transcript and result IDs, permits reordered parallel results while preserving their text exactly, counts forced-final against the same three-call allowance, retains transport receipts before releasing events, and becomes terminal on failure/cancellation/early close. Agent construction and fixed-prompt invocation are PRIVATE. Public `invoke_async`, `stream`, and `structured_output` refuse before Agent construction or execution; there is no public Agent builder. Test-only fixture subclasses exercise the private path with synthetic credentials and MockTransport.

The 299 passing tests include actual installed Strands1.53 planner/verifier typed-output loops over real bound PEX evidence tools, exact evidence observation bytes/hashes, parallel tools, forced-final counting, malformed replies/usage, one-attempt401/429/5xx/timeouts, no overflow recovery, committed-history rejection, and early-close/cancellation receipt retention.
