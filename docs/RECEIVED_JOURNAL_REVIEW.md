## Implemented boundary

The production attachment manager now allocates the inspection ID before creating the connector. Off-loop construction first commits an immutable requested-target record to `Settings.home / "codex-received.sqlite"`, then passes its journal to the real shared transport. Provenance includes requested PEX session, thread, project, cwd, socket and the workspace receipt at inspection. Those are requested/observed inspection facts, **not proof that every received payload belongs to that thread or that subscription was confirmed**. Confirmation never relabels the original record. Failed/expired attempts may remain as historical evidence.

Every nonempty, bounded connector read is committed before WebSocket/JSON parsing, filtering, notification routing or cleanup. This includes the HTTP upgrade, incomplete frames, unknown methods, server requests and malformed bytes. One read can contain multiple protocol messages. Payload bytes, SHA256, original endpoint/connection generation, inspection ID, local receipt timestamp and database sequence are retained. The timestamp is PEX receipt time, not vendor event time. Reopening the database read-only can recover committed evidence; nothing replays it into the live pump or restores old authority.

The new small journal module uses a separate local SQLite database, WAL and `synchronous=FULL`, with per-operation connections closed after settlement. A plain-file header preflight checks application/version markers before SQLite opens existing files; regressions compare foreign main/WAL bytes and absence of SHM creation. Header offsets were verified against the official [SQLite file-format reference](https://www.sqlite.org/fileformat.html#the_database_header). New files use mode 0600 on POSIX and inherit the existing PEX data-directory ACL on Windows. Regular-file identity is sampled on opening; this is not a malicious same-user filesystem lock or tamper-proof storage. Append-only triggers protect rows from normal UPDATE/DELETE; SHA256 checksums are not cryptographic authenticity against an actor able to edit the database.

Budgets are 1 GiB **payload bytes**, one million chunks and ten thousand inspection attempts, shared across this database. They are not a bound on total SQLite/WAL filesystem size. Full capacity refuses new records without deleting or rotating old evidence. Retention/archive UI is not implemented. Unknown schema, disk failure, changed journal identity, invalid chunk/provenance or regressing epoch fails closed. There is no automatic append retry or adoption of a damaged file.

The transport exposes separate complete-envelope and raw-chunk revisions. Pending received bytes become visible synchronously before waiting for the protocol lock, so a writer already queued ahead of the reader cannot pass a stale snapshot. Internal text dispatch now requires both expected revisions and a healthy settled journal. Partial bytes invalidate the old raw-chunk snapshot even when no full JSON envelope exists. Direct test/observer transports may omit a journal, but then text dispatch is refused; the production attachment path always supplies one.

Cancellation after a read has returned still settles the one append, including cancellation while waiting for the protocol lock. Journal cancellation settles the one owned disk task through repeated cancellation, then propagates cancellation and retires health. The wired producer is serial: one handshake then one reader under the protocol lock; this is not a guarantee for a hypothetical independent caller cancelled while queued behind another journal caller. Data from a retired epoch can remain durable but is not parsed/routed as current. Missing/failed journals cannot authorize a write; encountered journal failure refuses reopen on that transport. Normal generic shared mutations remain forbidden.

## Privacy and explicit limits

Raw received data can contain sensitive transcripts, unknown vendor fields, server request IDs or credentials echoed by the worker. It stays in the existing local PEX data directory: no HTTP, model, telemetry or cloud/export path was added. Exact database, WAL, SHM and rollback-journal filenames are gitignored and were checked with `git check-ignore --no-index`. Do not attach these files to a submission or copy their raw contents into reports. Existing lifecycle normalization/redaction and public coverage labels were not upgraded to full coverage.

This retains **committed, received connector bytes**, not bytes never returned by the connector, pre-attachment activity or proof of a complete stream. A crash before commit can still lose the current chunk; FULL synchronization is not immunity to disk/power failure. There is no durable clean-close marker, automatic recovery/replay, archive workflow, installed-worker proof, global input revision or cross-client transaction. Journal readiness does not prove the parser has no partial message or that the worker is idle. Fresh coordinator reconciliation and durable action authority are still mandatory before activation.
