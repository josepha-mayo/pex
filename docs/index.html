PEX

the judge for coding agents

Your coding agent says "all tests passed — I'm done." PEX doesn't take its word for it. PEX seals your intent up front, watches the agent's claims, and checks each one against the workspace itself — files, diffs, test exits — before anything is called finished.

What PEX is

  • A supervisor, not an agent — PEX sits above the coding agents you already run (OpenCode, Codex, Cursor). Worker narration is signal, never proof.
  • Sealed intent — your goal's acceptance surface is snapshotted at attach; mid-run tampering ("let me weaken that test") is caught as an integrity incident.
  • Bounded interventions — typed actions only (nudge · ask human · noop). Unresolved conflicts escalate to a durable human ruling, never an unbounded loop.
  • Rulings outlive sessions — a human's answer propagates to sibling sessions and survives goal amendments via supersedes lineage.
  • Workers call back — a scoped MCP server (9 tools, 6 scopes) lets an agent read its goal, report progress, preflight an intended action, verify a claim, or escalate an intent conflict itself.
  • Deterministic replays — 21 curated trajectories re-adjudicate through the real pipeline; identical arcs prove supervision is deterministic, not a lucky path.
